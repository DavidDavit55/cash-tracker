# Dated source reports (local implementation)

The report importer previews a single-client Maslaka ZIP/XML or Har Bituach workbook before any save. It resolves the subject against registered client identity; mismatches and mixed-client files are blocked. Dates are read from the source when unambiguous and presented for confirmation. Unknown dates remain blank; an as-of date is required. A received timestamp is generated by the database on save.

`client_report_snapshots` stores parsed payload and original file bytes in one insert, with source, as-of date, issue date, receiving administrator, filename and SHA-256. The schema is idempotent and is loaded by backend startup. No production migration has been run as part of this change.

Admin-only report list/save/download routes are mounted at `/api/admin/clients/:clientId/reports`. Downloads are scoped by both client and report IDs. Exact duplicate files for a client/source are rejected; there is no update or delete endpoint. This is separate from `client_financial_data`: neither imports through this new screen nor date selection modifies live data, reviews or drafts. Legacy bulk reprocessing is not exposed in the import screen. Legacy APIs elsewhere remain unchanged.

The client detail page and import screen display independent source selectors and the selected report's products, totals, coverage details and source download. Existing financial data without report provenance is not assigned invented report dates. Source-specific totals are not combined (the same insurance can occur in both sources).

Historical Maslaka parsing opts into retaining empty accounts and blocks a product-count mismatch with XML source records. Current legacy parsing keeps its prior defaults. Har Bituach premiums now preserve cents.

## Verification

- `node --test --test-isolation=none backend/report-snapshots.test.mjs`: dates, subject mismatch, malformed payload, source bytes, duplicate rejection, admin authorization, cross-client download denial and unchanged live review, using in-memory PostgreSQL only.
- From frontend: `node node_modules/vite/bin/vite.js build --configLoader native`.
- `node frontend/report-history-ui-check.cjs <har-workbook> <maslaka-zip> <screenshot-path>`: local browser, all API traffic intercepted. Checks preview before save, dates, full product count, independent selection, mismatch block and no save on date changes. Source files are read only. Personal source files and screenshots are not committed.

## Remaining scope

No production deployment or client data import was performed. Commissions migration, confirmed transfer events, side-by-side change comparison and promoting an approved snapshot into the live portfolio are not implemented by this slice. The new importer intentionally saves history only and says so at confirmation.
